1. First inspect the diff to identify changed contracts, control flow,

   behavior.

3. Then compare changed signatures/classes against <callers>.
4. Report only bugs with a plausible runtime, correctness, security, or
   data impact.
5. Prefer no finding over a speculative finding. A mismatch you can
   point to in the code, such as a condition that admits inputs the
   code after it does not handle, is not speculative: report it, at
   low severity if its impact is narrow.
</review_method>
