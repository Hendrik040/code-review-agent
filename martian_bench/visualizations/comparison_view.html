The Bench · code-review — BugsInPy + Martian Sentry, Opus 4.7

Section A · Agent SDK vs Client SDK

100 stratified Python bugs from BugsInPy across 17 projects, judged by Sonnet 4.5 against the maintainer's fix patch. Shown as 6 cells: agent_sdk and client_sdk at low, high, and max reasoning effort. Same model (Opus 4.7), same dataset, same judge — what differs is just the SDK and the effort level.

A1 · F1 by effort

F1 (strict) is 2·P·R / (P+R) where match = "finding identifies same bug as the maintainer's fix" (LLM judge). Simplest single-number ranking — read it as headline quality.

A2 · Recall curves: target vs broad

Solid line = caught the bug the maintainer fixed. Dashed = caught any real bug the judge accepts as legitimate (the ansible#9-style case where the agent finds a different real issue). Gap between the two = "bonus value" the agent provides.

A3 · Recall vs Cost — the Pareto

Each marker = (SDK, effort) cell. Top-left is best (high recall, low $). Slope of each curve shows the cost-of-each-percentage-point — agent SDK's curve is consistently cheaper at the same recall as client SDK.

A4 · Cost-per-target-bug

Total sweep $ ÷ bugs the agent actually caught. The "what does it cost to surface one real fix" number — the unit-economics view that matters for a $/bug commercial pitch.

A5 · Per-project recall heatmap

Target recall split by upstream project × cell. Reveals where the harness struggles (ansible, black, fastapi → systematically 0%) vs where it shines (PySnooper, cookiecutter). Diagnostic for what kinds of bugs the model class actually catches.

A6 · Full numerical matrix

All scored metrics, per cell. Source of truth — every other chart is a view onto these rows.

Section B · Martian Sentry — vs commercial tools

Martian's public 10-PR Sentry slice from withmartian/code-review-benchmark. Same goldens, same Sonnet-4.5 judge prompt as Martian's published leaderboard, so our F1 is directly comparable to the commercial tools' published numbers (filtered to the 10 Sentry PRs only). Curated to 7 commercial tools spanning above, near, and below us — leaderboard had ~40 entries but most were variants of the same tool.

B1 · F1 ranking — sorted

The simplest pitch chart. Bars sorted descending; our agent and client cells in their own colors against the gray commercials. Read top → bottom: where do we land?

B2 · Precision vs Recall

Each tool is a point. Top-right is "perfect"; the diagonal of equal P/R is a crude balance line. Reveals shape — high-P low-R = silent; low-P high-R = noisy.

B3 · Recall ranking

If the question is "of the bugs maintainers actually fixed, what fraction did the tool surface?" — recall is the more honest answer than F1. Some commercials look better here than on F1.

B4 · Precision ranking

"When the tool flags something, how often is it right?" Some commercials score higher than us on precision but much lower on recall (silent + sharp).

B5 · Full ranking table

All commercial scores filtered to the 10 Sentry PRs only. Our six cells interleaved by F1.

Caveats. N is small for Martian (10 PRs); confidence intervals on F1 are wide — treat the ranking as directional, not statistically conclusive. BugsInPy bench is N=100 stratified Python bugs; the judge is Sonnet 4.5 and labels each finding twice (matches-maintainer + is-real-bug). Costs are real Anthropic API spend; commercial costs are not directly comparable (those tools have subscription pricing).
